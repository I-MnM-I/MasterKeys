# Per-LED Lighting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make lighting device-neutral, so the Apex 3 (on Linux and Windows) and the Redragon K745 PRO over cable get every effect drawn on their own LEDs.

**Architecture:** Each supported model is described by a `DeviceInfo`, a list of LEDs with positions and keys. The model gets a driver behind a generalised `Lighting` trait and an output loop of its own, which reuses the existing reconnect loop as the hotplug scan. `Renderer` works per device: it samples the existing `EffectEngine` along a strip of `strip` columns at each LED's x. With the Apex 3's `strip = 10` and zone centres, its output is identical to 0.2.0. Per-key custom colours for devices other than the Apex 3 live in a new `LightingState.custom` map. The Apex 3's custom colours stay in `Effect::Custom { colors }`, so 0.2.0 profiles need no migration code.

**Tech Stack:** Rust 2024 workspace, hidapi 2.6.7 (`linux-native-basic-udev` / `windows-native`), zbus 6, Slint, tokio. The K745 layout generator is Python 3 (stdlib only).

**Spec:** `docs/superpowers/specs/2026-11-26-lighting-design.md`

## Global Constraints

- Never send `00 09 00` to an Apex 3.
- The K745 driver sends only the volatile lighting frame: feature report ID `0x06`, byte 1 `0x06`, 520 bytes. It never sends any other command, and sends at most one frame every 35 ms.
- K745 wired match: VID `0x258a`, PID `0x010c`, interface 1, usage page `0xFF00`, and a report descriptor declaring a 520-byte feature report with ID `0x06`. Anything else is not opened.
- No code is copied from GPL projects (OpenRGB, mouse_m908). Redragon's `KB.ini` is not committed; only the layout generated from it is.
- Profiles saved by 0.2.0 load unchanged. No `deny_unknown_fields` is added anywhere.
- GUI builds and the full test suite run in the `rexbuild` distrobox: `distrobox enter rexbuild -- bash -lc 'cd /var/home/imnmi/Documents/Apps-Games/MasterKeys && cargo test --workspace --no-fail-fast'`.
- The Windows check: `cargo clippy --workspace --all-targets --target x86_64-pc-windows-gnu -- -D warnings` in rexbuild, and `cargo clippy --workspace --all-targets -- -D warnings` for Linux. Both stay clean after every task.
- Tests never open real hardware. Tasks use fakes or `device: false`.

## Rulings carried from the spec

- The spec says custom colours become a map with the Apex 3's under `"apex3"`. Instead, the Apex 3's custom colours stay in `Effect::Custom { colors }` (10 entries) and the other devices' go in `LightingState.custom`. This gives the same behaviour with zero migration and full 0.2.0 round-trips. Cost if wrong: one more migration later if a third zone device appears.
- The spec says "the `KB.ini` facts are committed under `tools/`". Instead, only the generator script and its output layout are committed, because `KB.ini` is Redragon's file. Cost if wrong: a re-check needs the installer, which is public.
- The spec says "the output task scans every 3 s". Instead, each model has its own output loop, and its reconnect backoff is set to max 3 s. That is the scan. Cost if wrong: none for two models.

## Review Focus

1. A K745 in 2.4 GHz or Bluetooth mode (receiver `3554:fa09`) must never be opened. The match is exact on `258a:010c` plus the descriptor check. Covered by `matcher_rejects_wireless_and_wrong_interface` in Task 4.
2. Unplugging one device while another is connected must leave the other updating, and both must reconnect. Covered by `one_device_failing_leaves_the_other_running` in Task 5.
3. Setting a K745 key colour while the effect is animated switches to Custom without blanking the Apex 3: the Apex 3 keeps its currently shown colours. Covered by `led_colour_keeps_apex_colours` in Task 6.
4. Brightness 0 to 100 on the K745 scales the colours, and 0 sends black instead of skipping the write. Covered by `k745_brightness_scales_and_zero_is_black` in Task 4.
5. A 0.2.0 profile JSON (no `custom` key) loads, and a new profile still has the 0.2.0 fields. Covered by `old_profile_loads_and_new_keeps_old_fields` in Task 3.

**Interfaces:**
- Produces:

```rust
pub trait Lighting: Send {
    fn info(&self) -> &DeviceInfo;
    /// One colour per `info().leds`, same order.
    fn write(&mut self, colors: &[Color]) -> steelseries_gg::Result<()>;
    fn set_brightness(&mut self, percent: u8) -> steelseries_gg::Result<()>;
}
pub type Opener = Box<dyn FnMut() -> steelseries_gg::Result<Box<dyn Lighting>> + Send>;
pub fn apex3_opener() -> Opener;   // wraps Apex3Device; write() converts to [Color; ZONE_COUNT]
pub fn k745_opener() -> Opener;    // redragon::K745::open()
```

```rust
// redragon.rs
pub const K745_VID: u16 = 0x258a;
pub const K745_PID: u16 = 0x010c;
pub const FRAME_LEN: usize = 520;
pub const MIN_GAP: Duration = Duration::from_millis(35);
pub fn matches(vid: u16, pid: u16, interface: i32, usage_page: u16) -> bool;  // exact 258a:010c, iface 1, page 0xFF00
pub fn has_lighting_report(descriptor: &[u8]) -> bool;  // feature report ID 6 whose size*count = 519 bytes of payload (520 with ID)
pub fn encode_frame(leds: &[Led], colors: &[Color], brightness: u8) -> [u8; FRAME_LEN];
pub struct K745 { /* HidDevice, DeviceInfo, brightness, last_sent: Instant */ }
impl K745 { pub fn open() -> steelseries_gg::Result<K745>; }
```

- The frame is all zeros except these bytes:
  - `[0]=0x06`
  - `[1]=0x06`
  - `[4]=0x01`
  - `[6]=0x80`
  - `[7]=0x01`
  - `[8 + led.index]` = R
  - `[134 + led.index]` = G
  - `[260 + led.index]` = B
- Each channel is scaled as `c * brightness / 100`, rounded down.
- `write` sleeps until `MIN_GAP` has passed since the last frame, then calls `send_feature_report`.
- `set_brightness` only stores the value. The output loop rewrites the frame afterwards; see Task 5.
- `has_lighting_report` walks HID short items and tracks Report ID (`0x85`), Report Size (`0x75`), Report Count (`0x95`/`0x96`) and Feature (`0xB1`). It returns true when report ID 6 has a Feature main item totalling 519 payload bytes. Global state carries across items, as the HID spec says.
- `open` enumerates with `HidApi`. It requires `matches(...)`, then reads the descriptor with `get_report_descriptor` (4096-byte buffer) and requires `has_lighting_report`. Otherwise it returns `Error::DeviceNotFound`-style "no K745 PRO (wired)".
