# Milestone 3: GUI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `masterkeys`, a Slint window that controls the daemon. Its centrepiece is a drawing of the Apex 3 whose keys show live zone colours (animations included) and light up as you type. Around it sit colour, brightness and effect controls and a status bar.

**Architecture:**
- **Daemon additions:** `masterkeysd` gains a read-only key reader (evdev, never grabbed) and `SubscribeKeys` / `UnsubscribeKeys`. `KeyEvent` signals go **only to subscribed clients** (unicast), only while someone is subscribed, and a subscriber that disconnects is dropped.
- **Shared renderer:** the `Renderer` moves from `masterkeysd` into `masterkeys-core`, so the GUI can render the same frames locally for its live preview. No 60 fps frame stream crosses D-Bus.
- **GUI structure:** the GUI is a Slint UI (`ui/*.slint`, compiled by `slint-build`). A background thread runs a tokio runtime holding the D-Bus proxy and talks to the UI through channels and `slint::invoke_from_event_loop`. Pure logic (layout file, view colours, effect builder) lives in plain Rust modules with tests.

**Tech Stack:** Rust 1.99.1, `slint` 1.18.1 (+ `slint-build`), tokio, zbus 6.2.1, `evdev` 0.13 (tokio feature), `toml`, `serde`.

**Spec:** `docs/superpowers/specs/2026-11-08-masterkeys-design.md` (milestone 3; "`masterkeys` (GUI + tray)" → keyboard graphic, lighting panel, status bar)

## Global Constraints

- **Build in the `rexbuild` distrobox.** The host lacks the fontconfig/xkbcommon/wayland/freetype headers: `distrobox enter rexbuild -- cargo …` from the repo root. Binaries run on the host. Non-GUI crates still build and test on the host.
- **Function first.** Use Slint's stock `std-widgets` and the Fluent dark style. There's no custom theme, and polish is a later milestone.
- **Layout:** US ANSI full size, 104 keys, units where 1u = one standard key width. File: `assets/layouts/apex3-ansi.toml`.
- **Key privacy:** the daemon opens the keyboard's evdev nodes **read-only, never grabbed**, only while at least one client is subscribed. It emits `KeyEvent` with a **destination** of each subscriber, never as a broadcast. Subscribers whose bus name disappears are removed.
- **D-Bus additions** (interface `org.masterkeys.Daemon1`): `SubscribeKeys()`, `UnsubscribeKeys()`, signal `KeyEvent(q code, b pressed)` where `code` is the Linux evdev key code (`KEY_A` = 30).
- **Live preview:** 30 fps. Preview colour = zone colour × brightness/100.
- **Status bar text** (exact): `Connected` · `Keyboard not found` · `Daemon not running`. When the daemon isn't running, a **Start daemon** button runs `systemctl --user start masterkeysd`.
- **Effects offered in the UI:** Static, Breathing, Spectrum, Wave, Gradient, Off. Reactive is not offered (M5).

## Review Focus

1. **Daemon stops or restarts while the GUI is open** → the status changes to `Daemon not running` within 2 s, the controls disable, and the GUI reconnects and re-subscribes to keys on its own when the daemon returns. (Task 4 test)
2. **GUI crashes or is killed without unsubscribing** → the daemon drops the subscriber on `NameOwnerChanged`, and with no subscribers left it closes the evdev nodes. (Task 2 test on the subscriber set, plus a Task 6 manual check)
3. **The same key arrives on two interfaces** (the Apex 3 reports keys on both its boot and its NKRO interface) → one `KeyEvent` per real press/release, never duplicated, and no stuck "pressed" key. (Task 2 test)
4. **Invalid hex typed in the colour field** → the field shows an error state and nothing is sent. (Task 3 test on the input parser the UI uses)
5. **Keyboard unplugged while the GUI is open** → the status changes to `Keyboard not found`, the preview keeps the last state, and pressed-key highlights clear. (Task 4 test for status, plus a Task 6 manual check)

### Task 2: Daemon key events

**Files:**
- Create: `crates/masterkeysd/src/keys.rs`
- Modify: `crates/masterkeysd/src/service.rs`, `crates/masterkeysd/src/main.rs`, `crates/masterkeysd/Cargo.toml` (add `evdev = { version = "0.13", features = ["tokio"] }`), `crates/masterkeys-core/src/dbus.rs` (proxy additions)
- Test: unit tests in `keys.rs`, plus additions to `crates/masterkeysd/tests/dbus.rs`

**Interfaces:**
- Produces:
  - `keys.rs`: `pub struct PressTracker` with `pub fn new() -> Self`, `pub fn feed(&mut self, code: u16, value: i32) -> Option<(u16, bool)>`. Value 1 = down, 0 = up, 2 = autorepeat. It returns `Some` only on a real transition across all interfaces combined: down when the key wasn't held, up when it was. Autorepeat gives `None`. `pub fn release_all(&mut self) -> Vec<(u16, bool)>` returns ups for every held key.
  - `pub struct Subscribers` with `add(&mut self, name: OwnedUniqueName) -> bool` (true if this is the first subscriber), `remove(&mut self, name: &str) -> bool` (true if that left none), `names(&self) -> impl Iterator<Item = &OwnedUniqueName>`, `is_empty()`.
  - `pub async fn read_keys(events: mpsc::Sender<(u16, bool)>, stop: watch::Receiver<bool>)`: opens every evdev device with vendor `0x1038`, product `0x161A` that supports `EV_KEY` (no grab), merges their streams through one `PressTracker`, sends transitions, and on `stop` or a device error sends `release_all()` and returns.
  - Service: `subscribe_keys(&self, #[zbus(header)] hdr)` records the caller's sender and starts the reader on the first subscriber. `unsubscribe_keys` removes it and stops the reader when none are left. A task watches `org.freedesktop.DBus.NameOwnerChanged` (new owner empty) and removes vanished subscribers. Each transition is emitted as `KeyEvent(code, pressed)` once per subscriber, using `SignalEmitter::set_destination`. Log at `info`: subscriber added/removed (with its bus name) and key reader started/stopped. Never log key codes.
  - Proxy (`masterkeys-core::dbus`): `subscribe_keys`, `unsubscribe_keys`, signal `key_event(code: u16, pressed: bool)`.

### Task 4: Daemon client thread

**Files:**
- Create: `crates/masterkeys/src/client.rs`
- Test: `crates/masterkeys/tests/client.rs`

**Interfaces:**
- Produces:
  - `pub enum Command { SetAll(Color), SetZone(u8, Color), SetBrightness(u8), SetEffect(Effect), StartDaemon }`
  - `pub enum Event { Status(Status), State(LightingState), Key(u16, bool), Error(String) }`, with `pub enum Status { Connected, KeyboardNotFound, DaemonNotRunning }`
  - `pub fn spawn(on_event: impl Fn(Event) + Send + 'static) -> mpsc::UnboundedSender<Command>`: starts a thread with its own tokio runtime and connects to the session bus. While the daemon isn't there it reports `DaemonNotRunning` and retries every 1 s. Once connected it calls `GetState` (emitting `Status` + `State`), subscribes to keys, listens to `StateChanged`, `DeviceConnected` and `KeyEvent`, and watches `NameOwnerChanged` for `org.masterkeys.Daemon` so it notices the daemon leaving. When the daemon leaves it emits `DaemonNotRunning`, releases every held key with `Key(code, false)`, and goes back to retrying. Command failures emit `Error(message)`. `StartDaemon` runs `systemctl --user start masterkeysd` and reports a failure as `Error`.
  - `pub async fn run_on(conn: zbus::Connection, on_event, commands)`: the same loop on a given connection, used by the tests. `spawn` wraps it.
